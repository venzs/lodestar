# Lodestar

An addon suite for **WoW: Forever** (Classic+). Beta ends Oct 22 2026; launch is **Nov 4 2026**.
Core (`Lodestar/`) plus modules: `_Guide` (routes, arrow, harvest), `_Leveling`, `_Economy`, `_UI`,
`_Guild`, `_Character`, and two guide packs `_Guides_Horde` / `_Guides_Alliance`.

Lua 5.1, AceAddon/AceDB. The goal for launch is a clean 1-30 on both factions.

## Commands

```bash
tools/check.sh                 # THE gate: luacheck, apicheck, TOC/event/protected/anchor checks,
                               # guide lint, ~1,275 smoke checks, 4 cross-session persistence runs
tools/router/regen.sh [frag]   # rebuild generated routes from their own --regen-args header line
tools/router/lint_guides.py    # guide lint alone
tools/package.sh [version]     # build dist/Lodestar-<v>.zip (stamps the STAGED tocs, never source)
tools/refresh_harvest.sh       # import a /lode export paste -> merge -> regen
```

Needs `bash`, `lua5.1`, `luacheck`, `python3`, `git`. On Windows use Git Bash — every script here is
`#!/usr/bin/env bash`. Run `tools/check.sh` before considering anything done; it is fast enough that
there is no excuse not to.

## Data pipeline

Four sources merge into one world model, in this order (`Lodestar_Guide/Data.lua`):

1. `Data/Vanilla.lua` — GENERATED from pfQuest (`tools/pfquest/fetch.sh && import.py`). Needs
   `tools/pfquest/src/`, which is gitignored, so you cannot regenerate it without fetching first.
2. `Data/ATT.lua` — GENERATED from AllTheThings. Fills gaps under the harvest.
3. `Data/Forever.lua` — GENERATED by `tools/pfquest/merge_scan.py` from player harvests in
   `data/beta/`. First-hand beta observations; outranks the two above.
4. `Data/Curated.lua` — **the one hand-maintained file.** For positions no generated source can ever
   hold, because the thing has no spawn row: an object that exists only once a quest item is used, a
   mob that is summoned rather than spawned. Merged LAST and **gap-fill only** — a hand-typed
   coordinate always loses to a generated one, so an entry self-expires the day upstream learns the
   position. Every entry names its source and date; `approx = true` marks a position derived from
   prose rather than read off a map.

**Never hand-edit a generated file.** If a coordinate is wrong, fix it at the source or add a
curated entry.

The gap-fill rule is implemented three times — `Data.lua`, `tools/router/generate_route.lua`,
`tools/pfquest/query.py` — because they are three languages reading one file. Change one, change all
three. A linter checking guides against data the addon does not have is how a route passes lint and
points at nothing in game.

## Guide DSL

`Lodestar_Guide/Parser.lua` is the grammar; `tools/router/lint_guides.py` re-implements it for
checking. Steps are `step` + directives:

```
step
  .goto Zone,x,y
  .accept <id> >>text        .turnin <id>       .complete <id>[,objectiveIndex]
  .class <Class>             .race <Race>       .optional >>why
  .buy <item>[,n]            .item <id>         .train / .hs / .fly / .text / .xp <level>
```

Headers: `#guide`, `#faction`, `#race`, `#levels a-b`, `#next <guide>`, `#next Horde: <guide>` (a
neutral race like the Skyborne needs two successors), `#author`, `#note`.

`.complete <id>` with no index means "this step finishes the quest". `.complete <id>,<n>` watches ONE
objective — if the quest has more, the step goes green early and the route walks the player to a
turn-in the client will refuse. The linter checks objective coverage; a `.buy` of one of the quest's
own objective items counts as covering one.

## Conventions that were learned the hard way

**A wrong arrow is worse than no arrow.** Never invent a coordinate to fill a line. A step with no
`.goto` says "this is elsewhere", which is true; a step with a guessed position says something false,
confidently. Same for quest ids — a wrong id leaves the engine waiting forever for something that
never completes. Where the data does not know, say so in `.text` and let the harvest fill it in.

**A test that passes proves nothing until you have seen it fail.** Revert the fix, watch the test go
red, restore. This has caught a vacuous test at least once: a "does not overwrite" assertion that
passed happily with the rule inverted, because nothing in the file targeted the object it checked.

**Measure before building.** Several plausible fixes this project nearly shipped were rejected by
measurement first — Desolace's backtracking had three wrong hypotheses, and a plan to name the zone
an out-of-zone objective lives in would have sent players to the wrong zone for common drops.

**Do not duplicate logic across languages or modules.** Two hashes both answering "who is this" and
two copies of "does this step apply" both drifted; the second copy in each case was the one missing a
rule. One implementation, imported.

**TOCs are CRLF-pinned** by `.gitattributes` — the client reads them and every other addon on disk
ships CRLF. `sed 's/^## Version:.*/.../'` silently drops the `\r` from that one line. Use awk and
carry the ending across (`tools/package.sh` shows the pattern).

**The beta client never returns saved variables at login.** It writes them correctly and ignores them
on the way in. `Lodestar/Core/Vault.lua` keeps window positions and route progress in the client's own
CVars so they survive; anything else resets each session. This is the client, not the addon.

**Seasonal quests are excluded from generated routes** via pfQuest's `event` flag. They are disguised
in the data — pfQuest says level 60, ATT says 25, and the generator prefers ATT — so they arrive
looking like ordinary content while the giver NPC does not exist outside the holiday.

## Harvest

Players run `/lode export`, paste the blob back, and `tools/pfquest/import_paste.py` turns it into
`data/beta/scan-*.json` for `merge_scan.py`. Exports carry race, class, level and a **hash of the
character name**, never the name itself — `Lodestar.ContributorID` in `Core/Utils.lua`, one
implementation used by both `Export.lua` and `Harvest.lua`. The privacy statement in `Share.lua`,
`README.md` and the packaged `INSTALL.txt` must stay true to that; it has been wrong twice.

Forever-only quests (ids 90000+) are known by title and objective from an ID sweep, but have no giver
or position until someone accepts them with Lodestar running. The route generator only includes
quests whose giver it can place, so unharvested chains are silently absent rather than wrong.

## Open decisions

- Hillsbrad and Ashenvale route battleground quests (Warsong Gulch, Arathi Basin). Real and
  available, but arguably not levelling content. Undecided.
- Four Horde guides advertise a level band they do not carry (Ashenvale 25-30 carries 24-26;
  Thousand Needles 25-30 carries 27-29, so a level-25 player sees two routes both claiming 25-30).
  The linter warns; the names are a product decision and were left alone.
- Desolace backtracks 64%, worst of the generated routes. Diagnosed as camp spacing (median hop
  23.8, camps ~30% apart), not a router bug. **The batching radius is not the lever** -- swept over
  all seven generated routes (2026-09-20), a wider `HUB_RADIUS` makes them monotonically worse:
  mean backtracking 53.3% at 8, 54.1% at the shipped 12, rising to 58.6% at 36. Desolace itself
  reads 65/64/65/65/65/63/75% across that sweep, which is noise. That is the fourth wrong hypothesis
  about this zone; do not re-propose a per-zone radius without new evidence. The remaining suspect
  is the shape of a batch rather than its width -- collect-all, do-all, then one turn-in stop per
  quest, where a person hands things in on the way past -- but that is untested.
- Zephras Isle is missing the Skyborne faction-choice chain entirely (92595 The Windshapers /
  Windshaper = Horde, 92596 The High Order / High Order = Alliance, plus the mirrored kill quests
  94411 and 94413). Known by title only; no giver recorded, so the generator dropped all four.
  Needs one playthrough with Lodestar running.
